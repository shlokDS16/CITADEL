# API Contracts

This directory holds **per-module contract verification reports** generated by the `/contract-check` slash command (or the `api-contract-validator` agent).

## How it works

The flow when wiring backend ↔ frontend for a module:

```
docs/module-specs/<n>-<module>.md         ← source of truth (the contract)
            │
            ├── frontend (mock in pages.jsx)
            │       MUST match the spec
            │
            └── backend (Pydantic schemas in modules/<module>/schemas.py)
                    MUST match the spec

            ▼
    /contract-check <module>
            │
            ▼
    docs/api-contracts/<module>.md         ← drift report (this directory)
```

If frontend and backend disagree, **the spec wins**. Both sides come back to spec. Never let the implementations agree against the spec.

## File naming

One file per module, named after the module ID:
- `doc-intel.md`
- `resume.md`
- `traffic.md`
- `anomaly.md`
- `chatbot.md`
- `fake-news.md`
- `tickets.md`
- `expenses.md`

Each file is **append-only** — every contract check appends a new section with timestamp, never overwriting prior history. The latest section at the top is the current state.

## Severity legend
- 🔴 **CRITICAL** — type mismatch, required-vs-optional drift, enum drift, missing required field. Blocks `/connect-frontend`.
- 🟠 **WARN** — extra field on backend (forward-compat OK), extra field on frontend mock (will render undefined when wired live).
- 🟢 **INFO** — naming convention variation that's still valid.

## Action policy

- 🔴 CRITICAL → file `[ ]` items in `tasks/todo.md` immediately. Wiring is blocked.
- 🟠 WARN → tracked, not blocking. Address opportunistically.
- 🟢 INFO → noted, no action needed unless it accumulates.

## Re-running

After any spec change OR backend schema change OR frontend mock change for a module, re-run:
```
/contract-check <module>
```

The report is regenerated; the new section is timestamped and prepended.
